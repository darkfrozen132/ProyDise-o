Eres un desarrollador frontend experto. Necesito que implementes la integración de un sistema de simulación logística en tiempo real que usa WebSocket STOMP.

CONTEXTO:
El backend está en Spring Boot y expone una API REST para controlar simulaciones y un WebSocket STOMP para recibir actualizaciones en tiempo real. El sistema simula la planificación de rutas logísticas usando un algoritmo genético.

ARQUITECTURA DEL BACKEND:

1. REST API - Control de Simulación:
   - POST http://localhost:8000/api/simulations/start
     Body: {"fecha": "2025-01-02", "factorK": 5}
     Response: {"sessionId": "uuid", "mensaje": "...", "topicUrl": "/topic/simulations/{uuid}"}
   
   - POST http://localhost:8000/api/simulations/{sessionId}/cancel
   - POST http://localhost:8000/api/simulations/{sessionId}/pause
   - POST http://localhost:8000/api/simulations/{sessionId}/resume

2. WebSocket STOMP - Actualizaciones en Tiempo Real:
   - URL: ws://localhost:8000/ws
   - Protocolo: STOMP sobre SockJS
   - Topic: /topic/simulations/{sessionId}
   - Dependencias: sockjs-client, @stomp/stompjs

REQUISITOS DE LA INTERFAZ:

1. Panel de Control:
   - Input para fecha (date picker) - ÚNICO CAMPO QUE DEBE INGRESAR EL USUARIO
   - Factor K se envía automáticamente con valor 5 (NO mostrar en UI)
   - Botón "Iniciar Simulación"
   - Botón "Cancelar Simulación" (solo activo durante simulación)

2. Panel de Progreso:
   - Barra de progreso visual (0-100%)
   - Mostrar: Generación actual / Total generaciones
   - Mostrar: Mejor fitness encontrado
   - Mostrar: Pedidos procesados / Total pedidos
   - Mostrar: Tiempo simulado actual

3. Panel de Visualización (opcional pero recomendado):
   - Lista de rutas generadas
   - Información de vuelos en cada ruta
   - Métricas de la solución (costos, tiempos, etc.)

4. Panel de Logs:
   - Consola de mensajes en tiempo real
   - Mostrar cada generación completada
   - Mostrar eventos importantes (inicio, fin, errores)

FLUJO DE TRABAJO:

1. Usuario ingresa SOLO la fecha (el factor K es siempre 5, no lo pidas al usuario)
2. Usuario hace clic en "Iniciar Simulación"
3. Frontend envía POST a /api/simulations/start con {fecha: "valor-ingresado", factorK: 5}
4. Backend responde con sessionId y topicUrl
5. Frontend conecta WebSocket y se suscribe al topic
6. Frontend recibe mensajes en tiempo real y actualiza UI
7. Cuando status === 'COMPLETED', desconectar WebSocket
8. Si usuario cancela, enviar POST a /api/simulations/{sessionId}/cancel

NOTAS IMPORTANTES:

- TODOS los campos JSON están en ESPAÑOL (fecha, factorK, generacion, mensaje, etc.)
- El Factor K SIEMPRE es 5 - NO pidas este valor al usuario, envíalo automáticamente
- Solo pide al usuario la FECHA de inicio de la simulación
- El WebSocket usa SockJS como fallback para compatibilidad
- El ALGORITMO GENÉTICO REAL está activo: cada iteración ejecuta 20 generaciones completas
- La simulación tardará VARIOS MINUTOS (5-10 minutos para 4440 pedidos)
- Recibirás mensajes de progreso del AG (tipo PROGRESO_AG) con las rutas reales generadas
- También recibirás snapshots de simulación (status: RUNNING/COMPLETED)
- Implementa reconexión automática del WebSocket
- Maneja errores de conexión y timeouts
- Muestra AMBOS tipos de progreso: generaciones del AG + iteraciones de la simulación
